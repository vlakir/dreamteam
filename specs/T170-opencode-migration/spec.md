# Spec: Миграция dreamteam на OpenCode

**Статус:** Implemented; приёмка и ограничения — acceptance.md
**Дата создания:** 2026-10-15
**Основание:** решения Владимира в рабочей сессии миграции.

## 1. Цель и границы

Dreamteam полностью переходит на OpenCode и OpenCode Ensemble. Методика,
проектные особенности, долговременные знания и проверяемый процесс разработки
сохраняются. После приёмки Claude Code и клиент Codex удаляются на ноутбуке
и в серверном окружении; архивы знаний и истории сохраняются отдельно.

База разработки — опубликованный релиз dreamteam 1.7.0, commit 939fb07.
Разработка ведётся на devbox в ветке migration/opencode. Семнадцать коммитов
между релизом и проверенным origin/main не включаются. В релизе отсутствуют
позднейшие dt context, реестр сессий и dt resume: их реализации не переносим.
Требования к новым средствам восстановления определяются сценариями ниже.

## 2. Сценарии использования

- Создать или обновить проект с единой методикой и его собственными правилами.
- Поставить задачу команде; наблюдать статусы, переписку и результат в дашборде.
- Исполнителям напрямую согласовать общий интерфейс или зависимость задачи.
- После сжатия контекста или перезапуска восстановить задачу и её ограничения.
- Сменить API-провайдера без переделки методики, памяти и структуры проектов.
- Использовать ChatGPT Plus/Pro как дополнительный маршрут доступа к моделям.

## 3. Обязательные требования

- OpenCode является обязательной платформой dreamteam; совместимость с другими
  агентными клиентами не поддерживается.
- Настройка PyCharm и Zed относится к личному окружению Владимира и не является
  зависимостью библиотеки или сгенерированных проектов.
- Новые шаблоны, инструкции, роли, команды и конфигурация ориентированы только
  на OpenCode. Существующие проекты обновляются с сохранением их особенностей.
- Anthropic Pro/Max и возвращающие их OAuth плагины исключены по решению
  Владимира. Claude доступен через API. ChatGPT Plus/Pro остаётся в объёме;
  клиент Codex для него не должен быть обязательной зависимостью.
- Dreamteam — публичная библиотека, независимая от провайдера. Основного
  провайдера на уровне библиотеки нет. Пользователь выбирает поддерживаемый
  OpenCode облачный, локальный или совместимый API endpoint через конфигурацию.
  Роль агента, модель и маршрут подключения разделены. Шаблоны не содержат
  обязательных моделей, адресов и переменных окружения конкретного провайдера.
  Секреты не включаются в репозиторий, шаблоны и диагностические отчёты.
- PlusVibe API — личный выбор Владимира для его развёртывания. В публичной
  документации допустим как необязательный пример подключения наравне с другими
  маршрутами; для работы dreamteam регистрация в PlusVibe не требуется.
- Протокол выбирается по фактическим возможностям endpoint и модели. Нельзя
  объявлять кэширование, reasoning, изображения или специальные инструменты
  работающими только на основании успешного текстового ответа.
- Подключаются существующие mem0 и tools MCP с сохранением идентичности и
  областей памяти. Недоступность mem0 не отменяет файловые правила методики.
- Локальная память инвентаризируется и переносится с указанием происхождения;
  устаревшие сведения не становятся актуальными только из-за переноса.
- У каждого изменяющего код исполнителя отдельный worktree. Учёт задач и
  статусов имеет один основной источник; доска Ensemble согласована с ним.
- Проверки, ревью, CI и правила интеграции изменений сохраняются. Статус
  исполнителя done не равнозначен принятому и проверенному результату.

## 4. Приёмка

1. Зафиксирована совместимая пара релизов OpenCode и Ensemble. v1.19.0 —
   обнаруженный стабильный релиз OpenCode; перед установкой проверить актуальность,
   протоколы плагинов и доступность нужных возможностей именно в этом релизе.
2. Init и update проходят на тестовом проекте; пользовательские особенности
   сохраняются. Проверены все поддерживаемые языки шаблона.
3. На живом API проверены текст, изображения у vision-модели, несколько циклов
   инструментов, reasoning при наличии, streaming, отмена и обработка ошибок.
4. Повторён достаточно длинный стабильный префикс; зафиксированы доступные
   cache read/write usage и данные тарификации. Если наблюдаемость отсутствует,
   результат отмечен как неподтверждённый. Перезапуск кэш не обязан сохранять.
5. Два исполнителя обмениваются прямыми сообщениями; проверены доставка занятому
   и простаивающему участнику, зависимости задач и отображение в дашборде.
6. Проверены восстановление после перезапуска, сохранение знаний после compaction
   и отсутствие повторного выполнения уже завершённых действий.
7. Поиск mem0 возвращает прежние знания в правильной области; проверена запись
   контрольного факта и работа при недоступности памяти без потери правил.
8. Выполнена одна реальная ограниченная задача до зелёных проверок, ревью и
   интеграции. Подтверждён вход ChatGPT Plus/Pro без установленного клиента Codex.
9. Сохранены знания и нужная история; составлен перечень установок и сервисов.
   После перехода остановлены и удалены старые клиенты и зависящие от них
   служебные запуски на согласованных хостах; OpenCode продолжает работать.

10. Публичные шаблоны и пакет работают без учётной записи PlusVibe. Смена
    провайдера выполняется конфигурацией без изменения кода, ролей и методики.
    Автоматические проверки не требуют личных ключей и платного доступа;
    результаты живых проверок моделей учитываются отдельно для каждого маршрута.

## 5. Этапы

Сначала инвентаризация релиза, окружения devbox, локальной памяти и зависимых
сервисов. Затем фиксируются версии и разрабатываются шаблоны, роли и безопасное
обновление проектов. Следом подключаются MCP и маршруты моделей, проверяется
командный цикл и восстановление. После пилотной задачи выполняются перенос
проектов и удаление прежних клиентов. Для каждого этапа сохраняются результаты
проверок; неподтверждённые возможности не маскируются успешностью других этапов.

## 6. Открытые технические вопросы

- Какой релиз OpenCode совместим с Ensemble без опоры на неопубликованный V2?
- Как сохранить принятые пути, имена веток и процесс интеграции worktrees?
- Как соотнести существующую доску dreamteam и задачи Ensemble без расхождения?
- Как выявлять и проверять доступные протоколы и возможности выбранного
  пользователем endpoint? В личном пилоте Владимира проверить PlusVibe,
  сохранив общий механизм конфигурации и проверок для других провайдеров.
- Нужна ли связь между независимыми командами сверх сообщений внутри одной?
- Какие сервисы, включая Telegram, сейчас зависят от удаляемых клиентов?

## 7. Ограничения

Прямое восстановление Claude JSONL как живой OpenCode-сессии не обещается:
для активных задач готовится передача контекста, история сохраняется в архиве.
Все связанные с удалением клиентов сервисы сначала учитываются и заменяются.
Автоматическое слияние в main, публикация релиза и перезапись общей истории
этой спецификацией не предписываются.
