# Приёмка миграции на OpenCode

Дата: 2026-10-15. Статус: библиотека реализована, живые пилоты пройдены,
личный runtime переключён. Ниже отдельно перечислены ограничения и проверки,
требующие настоящего окна IDE или участия пользователя.

## Реализовано в библиотеке

- Правила AGENTS.md и .opencode вместо новых Claude Code артефактов во всех
  пяти языках шаблона. Провайдеры и модели остаются пользовательской настройкой.
- Обязательный OpenCode 1.19.0; Ensemble закреплён на опубликованной версии 0.18.0.
  Версия 0.19.0 из main Ensemble не опубликована в npm и не используется.
- Read-only Architect с нативными permissions, наследованием модели при отсутствии
  настройки и поддержкой provider/model-id. Старые алиасы при update заменяются
  на inherit с уведомлением.
- dt serve запускает постоянный сервер, dt run подключается к нему;
  --session передаёт идентификатор его сессии.
  dt doctor проверяет бинарник; --server и --path проверяют фактическую
  регистрацию основных инструментов Ensemble, не вызывая модель.
- Update сопоставляет переименованные файлы с исходным шаблоном, сохраняет
  пользовательские правки или возвращает конфликты. Исходные файлы Claude
  при переименовании сохраняются для проверки. Если отсутствует история для
  такого переноса, обычное update останавливается без записи.
- Автоматическое слияние веток при cleanup выключено. BOARD и BACKLOG остаются
  основным учётом проекта; Ensemble отражает исполнение.

## Ограничение Ensemble 0.18.0

Первый пилот обнаружил общий ensemble.db независимо от XDG_DATA_HOME:
другой процесс с отдельным хранилищем сессий архивирует чужую команду.
Инициализация плагина также помечает busy участников проекта stale.
Это ограничение upstream. Используется постоянный сервер и attach клиентов.
Одновременный standalone/ACP запуск для активной команды пока не принят.
Завершённый пилот пережил рестарт без изменения участников, задач и 11 сообщений.
Прерванный backend после dt recover продолжил ту же сессию и worktree: stage-one
и stage-two записаны ровно по разу, коммит dc7a89f. Автоматического возобновления
в Ensemble нет; используется явный адаптер восстановления с проверками владения
и резервной копией. Compaction проверен отдельным сценарием ниже. MCP и копии памяти остаются
в частном окружении, вне библиотеки.

## Доставка в main

Ветка разработки начинается непосредственно от 1.7.0. Обычное слияние такой
ветки с текущим main может сохранить изменения main после релиза. Для итогового
PR нужна отдельная ветка доставки на актуальном main, дерево которой точно
совпадает с принятым деревом migration/opencode. Проверить равенство деревьев
перед слиянием. Не переписывать общий main и не подтягивать отброшенные изменения
в ветку разработки. Этот этап выполняется после завершения приёмки.
