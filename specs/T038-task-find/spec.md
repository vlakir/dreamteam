## 1. Overview

Точка входа E1 (карточка T006, `deps: T034`). Путь от человеческой
формулировки к ID задачи: `dt task find "<фраза>"` ищет по заголовкам, телу,
тегам и именам веток, ранжирует и возвращает кандидатов. Ключевой
агент-сценарий (§326): человек упоминает задачу свободной фразой → агент
зовёт `find --json`, называет кандидата, ждёт подтверждения, затем
`dt task start`. Без эмбеддингов и внешних сервисов — корпус десятки файлов.

**Явно НЕ в этой задаче:** `dt task start` (T039); эмбеддинги/семантика;
нечёткая опечаточная коррекция (fuzzy edit-distance); индексы/кэш.

## 2. Сценарии использования

- **Агент от фразы к ID.** `dt task find "курсор полноэкранный режим" --json`
  → ранжированный список; агент называет топ-кандидата, ждёт «да».
- **Человек ищет задачу.** `dt task find "worktree"` — быстрый ранжированный
  список по релевантности.

## 3. Functional Requirements

- ДОЛЖНА: `find_tasks(store, query)` — чистая (typer-free, git-free) функция,
  возвращает ранжированный список `(Task, score)` с `score > 0`.
- ДОЛЖНА: нормализация — casefold + разбиение на токены по не-словам
  (Unicode-aware, кириллица включена); токены длины < 2 отбрасываются.
- ДОЛЖНА: искать по 4 полям с весами: **заголовок > теги/ветка > тело**
  (`title=3`, `tags=2`, `branch=2`, `body=1`).
- ДОЛЖНА: **морфология-толерантный** матч токенов по общему префиксу — токены
  совпадают, если длина общего префикса ≥ 4 (короче 4 — только точное
  совпадение). Так `«курсор»~«курсора»`, `«полноэкранный»~«полноэкранном»`
  (§326). Каждый токен запроса даёт **максимальный** вес поля, где он попал
  (не сумму по полям), сумма по токенам запроса.
- ДОЛЖНА: статус-множитель — активные (`todo`/`doing`/`review`) выше
  завершённых: `×1.0` для активных, `×0.5` для `done`/`dropped`.
- ДОЛЖНА: сортировка — `score` убыв., tiebreak `updated` убыв., затем ID.
- ДОЛЖНА: `dt task find "<фраза>"` (под `task`) — человекочитаемый вывод
  `T<NNN>  [status]  title  (branch)`; пустая фраза / нет совпадений →
  «no matches», exit 0.
- МОЖЕТ: `--json` → список полных записей плюс `score` каждого.

## 4. Success Criteria

- `find "курсор полноэкранный"` находит задачу с заголовком «…курсора…
  полноэкранном…» (морфология через префикс).
- Совпадение в заголовке ранжируется выше, чем то же слово только в теле.
- Активная задача выше завершённой при равном текстовом совпадении.
- Нет совпадений / пустая фраза → «no matches», exit 0.
- 4 гейта зелёные; coverage ≥ 80% на новом коде.

## 5. Key Entities

- **ScoredTask** — `(task: Task, score: float)`; результат ранжирования.
- **Веса полей** — `title=3`, `tags=2`, `branch=2`, `body=1`.
- **Статус-множитель** — active `1.0`, иначе `0.5`.
- **Порог префикса** — общий префикс ≥ 4 симв. (морфология без стеммера).

## 6. Assumptions & Constraints

- Корпус — десятки записей; полный проход в памяти на каждый запрос, без
  индексов (design §320).
- Русская морфология покрывается грубо (общий стем-префикс), не стеммером —
  сознательный компромисс recall↑ / precision↓ для агент-сценария
  «назвать кандидата, дождаться подтверждения».

## 7. Out of Scope

- `dt task start` (T039), эмбеддинги/семантика, fuzzy edit-distance,
  индексы/кэш, стоп-слова, языковой стеммер.
- `--limit`/пагинация (корпус мал; можно добавить позже при нужде).

## Clarify (согласовано опросником 2026-07-30)

### Resolved

- **Матч токенов** → «общий префикс ≥ 4» (морфология-толерантно): matches
  словоформы из §326, ценой лёгкого шума на коротких токенах. Альтернативы
  «точное совпадение» (пропускает словоформы) и «подстрока» (частично)
  отвергнуты.

### Взято по умолчанию

- Веса `title=3 > tags=2 = branch=2 > body=1`; статус active `1.0` / иначе
  `0.5`; каждый query-токен даёт max вес поля; сортировка score→updated→id;
  токены < 2 симв. отбрасываются; результат — все `score>0`.

## Analyze (Claude)

- 🟢 **A1. Слой.** `find_tasks` — в `dt/tasks.py` (typer-free, git-free,
  рядом с `load_all_tasks`/`check_tasks`); Typer-обёртка — новая команда
  `find` в `task_cli.py` под под-приложением `task`.
- 🟢 **A2. Токенизация.** `re.findall(r'\w+', text.casefold())` — `\w`
  Unicode-aware, ловит кириллицу и цифры; токены < 2 симв. отброшены как
  шум. Один и тот же токенайзер для запроса и всех полей.
- 🟢 **A3. Матч по префиксу.** `os.path.commonprefix` посимвольно; порог 4
  фиксирован (не доля длины) — предсказуемо и просто тестируется; для
  токенов < 4 — только точное равенство, чтобы «cli» не ловил «client».
- 🟢 **A4. Max, не сумма по полям.** Токен запроса даёт максимальный вес
  поля, где попал, а не сумму по всем полям — иначе длинное тело с повтором
  перебивало бы заголовок. Ранжирование остаётся управляемым весами.
- 🟢 **A5. `dropped` в выдаче.** Не исключаются (в отличие от `dt board`):
  найти отменённую задачу по фразе полезно (для возможного возврата), но
  статус-множитель `0.5` держит её ниже активных.
