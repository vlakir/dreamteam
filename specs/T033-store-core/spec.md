## 1. Overview

Первая задача эпика E1 (оперативный слой состояния задач) и первый шаг
критического пути `T033 → T034 → T051 → T052 → T053`. Вводит **фундамент**
слоя: резолв корня состояния `$DT_HOME`, ленивое создание каталогов
хранилища, вычисление `<slug>` рабочей копии и типизированную модель
записи задачи с чтением/записью, сохраняющей неизвестные поля.

Это **чистый библиотечный слой без пользовательских команд**. Никаких
`dt task new/show/move` — они приезжают в T034 поверх этого фундамента.
Задача поставляет функции и модель, на которые опирается весь остальной E1.

## 2. Сценарии использования

Проект без явных «пользователей» — библиотечный слой; сценарии описывают
вызовы будущими командами и хуками E1.

- Команда `dt task …` (T034) вызывает `ensure_store()` и получает готовые
  каталоги `store/tasks/` и т.д., независимо от того, из какого worktree
  её запустили.
- SessionStart-хук (T052) и statusline (T054) вычисляют `<slug>` текущей
  рабочей копии, чтобы читать/писать `by-worktree/<slug>/`.
- `dt board` (T037), `dt task show` (T034) загружают запись задачи в
  типизированную модель, правят поле и сериализуют обратно — **чужие
  поля, которых код не знает, при этом не теряются** (forward-compat с
  будущими версиями формата).

## 3. Functional Requirements

**Резолв корня состояния (`$DT_HOME`):**

- ДОЛЖНА: вычислять `$DT_HOME` как `${DT_HOME:-<main-worktree>.dt}`, где
  `<main-worktree>` — родитель общего git-common-dir
  (`dirname "$(git rev-parse --path-format=absolute --git-common-dir)"`).
- ДОЛЖНА: давать один и тот же `$DT_HOME` из любого linked-worktree того
  же репозитория (worktree-независимость по построению — common-dir общий).
- ДОЛЖНА: уважать переопределение переменной окружения `DT_HOME` (аварийный
  обход, приоритет над вычислением).
- ДОЛЖНА: обрабатывать голый (bare) репозиторий: common-dir указывает на
  сам репозиторий (basename ≠ `.git`) → `<main-worktree>` = common-dir.
- НЕ ДОЛЖНА: работать вне git-репозитория без `DT_HOME` — внятная ошибка
  с подсказкой про `DT_HOME`.

**Slug рабочей копии:**

- ДОЛЖНА: вычислять `<slug>` как первые 8 hex-символов sha1 от абсолютного
  (разрешённого) пути **текущей** рабочей копии (`git rev-parse
  --show-toplevel`).
- МОЖЕТ: принимать явный путь аргументом (для тестов и будущих команд,
  считающих slug чужого worktree).

**Создание каталогов:**

- ДОЛЖНА: создавать `$DT_HOME` и подкаталоги (`store/`, `store/tasks/`,
  `store/sessions/`, `store/by-worktree/`, `worktrees/`) молча при первом
  обращении; операция идемпотентна.
- ДОЛЖНА: печатать **ровно одну** информационную строку в stderr **только**
  в момент самого первого создания корня `$DT_HOME` (когда его не было),
  с указанием пути.
- ДОЛЖНА: при недоступном для записи родительском каталоге выдавать внятную
  ошибку с подсказкой про `DT_HOME`, а не трассировку.
- НЕ ДОЛЖНА: создавать что-либо в git-репозитории или внутри `.git/`.

**Модель и сериализация записи задачи:**

- ДОЛЖНА: парсить файл записи `---\n<yaml frontmatter>\n---\n<markdown body>`
  в типизированную pydantic-модель + тело.
- ДОЛЖНА: **сохранять неизвестные поля** frontmatter при обратной записи
  (round-trip: `parse → serialize → parse` эквивалентен исходному по данным).
- ДОЛЖНА: валидировать `status` ∈ `{todo, doing, review, done, dropped}`.
- ДОЛЖНА: сериализовать в детерминированном порядке ключей (известные поля
  в каноническом порядке, неизвестные — следом, в исходном относительном
  порядке).
- НЕ ДОЛЖНА: включать `body` во frontmatter; тело идёт после второго `---`.

## 4. Success Criteria

- Резолв `$DT_HOME` даёт идентичный путь из основной рабочей копии и из
  любого `git worktree` того же репозитория (проверяется тестом с реальным
  linked-worktree).
- `DT_HOME=/custom` переопределяет вычисление.
- Первый вызов `ensure_store()` печатает одну строку в stderr и создаёт
  дерево каталогов; повторный вызов — тихий и не падает.
- `worktree_slug()` детерминирован: одинаковый путь → одинаковые 8 hex-символов.
- Round-trip записи с неизвестным полем (`custom_field: 42`) сохраняет его.
- Невалидный `status` → ошибка валидации pydantic.
- Coverage нового кода `src/dreamteam/dt/` ≥ 80% (жёсткий порог пакета).

## 5. Key Entities

- **`$DT_HOME`** — корень оперативного слоя, каталог-сосед `<repo>.dt`.
  Живёт вне git. Внутри: `store/` (записи, счётчик, сессии, привязки),
  `worktrees/` (рабочие копии задач).
- **`<slug>`** — 8 hex sha1 абсолютного пути worktree; ключ каталога
  `by-worktree/`, различающий параллельные рабочие копии.
- **`Task`** — запись задачи: frontmatter-поля (`id`, `title`, `status`,
  `deps`, `parent`, `spec`, `branch`, `pr`, `tags`, `created`, `updated`)
  + произвольные неизвестные поля (extra) + markdown-тело (контекст,
  критерии приёмки, `## Handover`).

## 6. Assumptions & Constraints

- Хранилище одно на репозиторий; параллельных копий состояния не существует
  (worktree-независимость), поэтому гонок на резолве путей нет.
- `git` доступен в PATH (общее допущение пакета; `_has_git()` уже есть).
- Целевые платформы — Linux/macOS основные, Windows поддерживается шаблоном;
  резолв путей — через `pathlib` и вывод git, без платформо-специфичного
  кода. `O_EXCL`-счётчик и flock — **не в этой задаче** (T034+).
- Новая runtime-зависимость: `pydantic>=2` (осознанный выбор Разработчика,
  ADR).

## 7. Out of Scope

- Любые Typer-команды `dt task/worktree/board/context/…` — T034 и далее.
- Счётчик ID и `O_EXCL` — T034.
- Запись/чтение `current-task` и `context.line` — T034 (`move`) / T039 (`start`).
- Реестр сессий `sessions/<TASK_ID>.json` — T052.
- Валидация целостности (`deps`-циклы, `parent`/`blocks`) — T035.
- Миграция BOARD.md → записи — T042.
- `git worktree list --porcelain`-резолв фактических путей — T036.

## Clarify (заполняется Claude)

### Resolved (с ответами)

- **Q (module layout): куда положить код?** → Подпакет `src/dreamteam/dt/`
  (`paths.py`, `model.py`; позже `commands/`). Оперативный слой отделён от
  scaffolding-CLI (`cli.py`). ADR в `DECISIONS.md`.
- **Q (модель записи): dataclass / dict / pydantic?** → **pydantic**
  (`extra='allow'` для сохранения неизвестных полей, валидация `status`).
  Осознанно принята новая зависимость. ADR в `DECISIONS.md`.
- **Q (детект «самого первого создания»):** печатаем строку stderr, если
  корня `$DT_HOME` не существовало до вызова (создаём — печатаем один раз).
- **Q (что хэшируем для slug):** абсолютный разрешённый путь текущей рабочей
  копии из `git rev-parse --show-toplevel`; sha1, первые 8 hex.
- **Q (типы дат):** `created`/`updated` — `datetime.date` (yaml нативно
  парсит `2026-07-30` в date; round-trip чистый). `pr` — `int | None`.
- **Q (стиль YAML-списков):** блочный стиль (`default_flow_style=False`).
  Flow-стиль (`deps: [T003]`) в дизайн-документе — иллюстративный; блочный
  валиден и round-trip-стабилен. Косметическое расхождение, осознанное.
- **Q (пустые опциональные поля):** `exclude_none=True` при сериализации —
  `parent`/`spec`/`branch`/`pr`/`updated` не пишутся, если None (минимальный
  frontmatter, как в примерах §6.3). Списки `deps`/`tags` пишутся как есть
  (в т.ч. пустые).

## Analyze (заполняется Claude)

- 🟢 **Note.** `git rev-parse --path-format=absolute` требует git ≥ 2.31
  (2021). Допустимо: пакет уже требует современный git для T009-флоу.
- 🟢 **Note.** `worktree_slug()` по умолчанию читает `git rev-parse
  --show-toplevel` (текущий worktree), тогда как `$DT_HOME` — по common-dir
  (главный worktree). Это сознательно разные вещи: slug различает **рабочие
  копии**, корень общий на **репозиторий**.
- 🟡 **Warning → resolved.** pydantic `extra='allow'` кладёт неизвестные поля
  в `__pydantic_extra__`; `model_dump()` включает их **после** известных.
  Детерминированный порядок обеспечивается порядком объявления полей модели +
  стабильным порядком extra. Тест round-trip фиксирует это.
- 🟡 **Warning → resolved.** `body: str` не должен попадать во frontmatter:
  помечается `Field(exclude=True)` и отбрасывается при дампе; тело
  приклеивается вручную после `---`.
- 🟢 **Note.** Ошибки резолва/записи — через собственное исключение
  `DtHomeError` (внятное сообщение + подсказка `DT_HOME`), ловится будущими
  командами и мапится в код возврата на уровне CLI (T034).
- 🟢 **Note.** Bare-репозиторий и «вне git» — краевые; покрываются
  `DT_HOME`-override и тестом на сообщение об ошибке.
- Проход чистый: критических противоречий нет, реализация разблокирована.
