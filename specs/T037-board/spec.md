## 1. Overview

Точка входа E1 (карточка T005, `deps: T034`). Текстовое представление
kanban-доски задач в терминал — обзор состояния всех задач репозитория из
одного места. Ключевое требование дизайна: **сборка модели вынесена в
отдельную функцию** (чтение записей, отсев `dropped`, сортировка по
`updated`), переиспользуемую позже графической доской (E10, §604) — поэтому
модель отделена от форматирования сразу.

**Явно НЕ в этой задаче:** графическая доска и `dt board serve` (E10);
поиск (`dt task find`, T038); фильтры/пагинация.

## 2. Сценарии использования

- **Обзор.** Человек/агент: `dt board` — все незавершённо-релевантные
  задачи по колонкам статусов, свежие сверху.
- **Машинно.** `dt board --json` — структура `{columns: {...}}` для агента
  или последующей обработки.

## 3. Functional Requirements

- ДОЛЖНА: `board_model(store)` — чистая функция: загрузить все записи
  (`load_all_tasks`), **отсеять `dropped`**, отсортировать по `updated`
  **убыв.** (свежие первыми; записи без `updated` — в конец, порядок по ID).
  Возвращает плоский список `Task`. Не трогает git, не обходит worktree
  (хранилище одно на репозиторий).
- ДОЛЖНА: `board_columns(model)` — группировка модели по статусу в порядке
  потока `todo → doing → review → done` (без `dropped`), сохраняя порядок
  модели внутри колонки. Отдельно от `board_model` ради переиспользования.
- ДОЛЖНА: `dt board` (top-level, не под `task`) — рендер **секциями
  столбиком**: заголовок статуса, под ним строки `T<NNN>  [status]  title`.
  Пустые колонки статусов показываются заголовком (стабильная форма доски).
- ДОЛЖНА: `--json` → `{"columns": {"todo": [...], "doing": [...],
  "review": [...], "done": [...]}}`, каждый элемент — полная запись (как
  `dt task show --json`).
- ДОЛЖНА: на пустом store — валидный вывод (все колонки пусты), exit 0.
- ДОЛЖНА: ошибки резолва store → stderr + exit 1 без traceback.

## 4. Success Criteria

- `dt board` печатает 4 секции (todo/doing/review/done) в порядке потока;
  внутри — задачи свежими сверху; `dropped` отсутствуют.
- `dt board --json` — валидный JSON с 4 ключами-колонками.
- `board_model` покрыта юнит-тестами независимо от CLI (отсев dropped,
  сортировка, None-updated в конце).
- 4 гейта зелёные; coverage ≥ 80% на новом коде.

## 5. Key Entities

- **BoardModel** — плоский список `Task` (активные, отсортированы по
  `updated` убыв.). «Модель» в терминах §604: read + filter + sort.
- **Колонки** — `BOARD_STATUSES = TASK_STATUSES \ {dropped}` в порядке
  потока; группировка — презентационный слой поверх модели.

## 6. Assumptions & Constraints

- Корпус — десятки записей; сортировка/группировка в памяти, без индексов.
- `updated` может быть `None` (запись создана вручную без даты) — такие в
  конец, чтобы не всплывали ложно свежими.

## 7. Out of Scope

- Графическая доска, `dt board serve`, `--open` (E10).
- Фильтры по тегам/статусу, лимиты, пагинация.
- Боковые колонки side-by-side (сознательно: плохо читаемо при длинных
  RU-заголовках на узком терминале — согласовано опросником).

---

## Clarify (согласовано опросником 2026-07-30)

### Resolved

- **Рендер** → «секции столбиком» (не side-by-side): читаемо при длинных
  RU-заголовках, не зависит от ширины терминала. Отклонение от буквы дизайна
  («колонки»), обосновано практичностью; `--json` даёт структуру для машин.

### Взято по умолчанию

- Сортировка `updated` **убыв.** (свежие сверху), None — в конец, tiebreak
  по ID. Порядок секций — поток `todo→doing→review→done`. Пустые колонки
  показываются (стабильная форма).

## Analyze (Claude)

- 🟢 **A1. Модель отдельно от рендера.** `board_model`/`board_columns` —
  чистые, в новом `dt/board.py` (git-free, typer-free), по образцу
  `dt/worktrees.py`. Typer-обёртка — `board_cli.py`, регистрируется как
  top-level `app.command('board')` (не sub-app: у `dt board` пока нет
  подкоманд; `serve` придёт в E10 — тогда возможна конверсия в группу).
- 🟢 **A2. Сортировка None-updated.** Ключ сортировки помещает записи без
  `updated` после датированных (флаг + `-ordinal`), чтобы «пустая дата» не
  читалась как «самая свежая».
- 🟢 **A3. `dropped` только в модели.** Отсев `dropped` — в `board_model`
  (единая точка), чтобы графическая доска E10 не повторяла правило.
