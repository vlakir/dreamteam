## 1. Overview

Девятнадцатая по дизайну (карточка T019), репозиторный T051, эпик E9
(`deps: T034, T036`). Решает **потерю ориентации** после reboot/`/clear`
(§291): и человек, и агент теряют связь «эта сессия ↔ эта задача», потому что
живой процесс её не переживает. `dt context` отвечает на «где я и над чем
работаю», не требуя ни одного флага и не завися от памяти агента.

Ключ связи — **ветка/worktree** (§299): имя ветки уже кодирует ID задачи
(`T<NNN>-slug`), переживает и reboot, и `/clear`, и уже есть в методике. Задача
разрешается единым для всех команд порядком (§309): `DT_TASK` → ветка →
`by-worktree/<slug>/current-task` → непривязанная сессия (легальный режим, не
ошибка). Команда — «только чтение» плюс обновление строки статуса текущего
worktree; она же — источник контекста, который SessionStart-хук (T052) вложит
в новую сессию.

## 2. Сценарии использования

- **Старт после `/clear` (агент).** Договорились очистить контекст. Новая
  сессия: SessionStart-хук (T052) зовёт `dt context --hook` → в контекст
  вкладывается ID/заголовок/статус задачи, спека, `## Handover`, блокеры, PR —
  агент сразу знает, что продолжать, без вопроса «какую именно?».
- **Ориентация человека после reboot.** `dt context` в терминале worktree:
  задача, статус, ветка, где живёт worktree, расхождение BACKLOG.
- **Непривязанная сессия.** Обсуждение/разведка/проектирование вне задачи:
  `dt context` печатает признак непривязанности и список задач в `doing`,
  **без требований и предупреждений** (§339, §347).
- **Разошёлся каталог.** Сессия в основной копии, а задача живёт в отдельном
  worktree: `dt context` добавляет строку «задача T034 живёт в …» ещё до
  первой ошибки (§505).

## 3. Functional Requirements

### Разрешение задачи (`resolve_task_id`, чистая)

- ДОЛЖНА: применять порядок `DT_TASK` → ветка (`T<NNN>` в начале имени) →
  `by-worktree/<slug>/current-task` → `None` (непривязанная).
- ДОЛЖНА: считать кандидата валидным только если это `T[0-9]{3,}` (иначе
  пропускать к следующему источнику).
- ДОЛЖНА: если разрешённый ID **отсутствует** в store — не падать: считать
  сессию непривязанной, но пометить «висячий» ID в выводе.

### `dt context` — привязанная сессия

- ДОЛЖНА: печатать ID, заголовок, статус, ветку, путь к спеке, текст
  `## Handover`, блокеры и номер PR.
- ДОЛЖНА: **блокеры** = `deps` задачи со статусом ≠ `done` (то, что мешает
  взять её в работу; развилка B).
- ДОЛЖНА: печатать строку расхождения BACKLOG (см. ниже), если оно есть.
- ДОЛЖНА: печатать строку расхождения каталога — когда у задачи есть worktree
  (из `git worktree list` по её ветке), а текущий каталог ему не равен: «задача
  T<NNN> живёт в <путь>» (§505).
- ДОЛЖНА: обновлять `by-worktree/<slug>/context.line` текущего worktree строкой
  `context_line(task)` (для statusline, T054); `<slug>` — от cwd (развилка C).

### `dt context` — непривязанная сессия

- ДОЛЖНА: печатать признак непривязанности и список задач в `doing` (ID +
  заголовок), без предупреждений и требований.
- НЕ ДОЛЖНА: обновлять `context.line` (нечем).

### Строка расхождения BACKLOG (переиспользует T040)

- ДОЛЖНА: сравнивать store с BACKLOG.md **основной рабочей копии** (не текущего
  worktree, §217/§880) через `backlog_divergence`; печатать «BACKLOG.md
  отстаёт: +N заведено, −M завершена» при ненулевом расхождении.
- ДОЛЖНА: **пропускать** строку, если основной BACKLOG.md не содержит
  управляемого блока `dt backlog sync` (проект его не принял) — иначе на
  неадаптированном проекте показалось бы ложное «+всё» (развилка A).

### Режимы

- ДОЛЖНА: `--json` — структурированный объект (задача целиком или признак
  непривязанности; обе строки расхождения; список `doing` для непривязанной).
- ДОЛЖНА: `--hook` — печатать
  `{"hookSpecificOutput": {"hookEventName": "SessionStart", "additionalContext":
  "<выжимка>"}}`; бюджет `additionalContext` ≤ 2000 символов (обрезка с
  многоточием); **любая** ошибка → выход код 0 и пустой вывод (хук никогда не
  блокирует старт, §356).
- ДОЛЖНА: без `--hook` — обычное отображение; ошибки (`DtHomeError`/`OSError`)
  → stderr + exit 1 (образец `_run`).

### Общее

- ДОЛЖНА: неинтерактивность; быстро; без сетевых вызовов.
- ДОЛЖНА: чистое ядро (резолв, сборка модели контекста, рендер) — **typer-free
  И git-free**; git-факты (ветка, worktree-список, путь основной копии, текст
  BACKLOG) добывает обёртка из `paths.py`. Повторяет T035/T037/T040.
- НЕ ДОЛЖНА: читать транскрипты `~/.claude/projects/**/*.jsonl` (§358).

## 4. Success Criteria

- В worktree задачи `T034-*`: `dt context` показывает T034, статус, ветку,
  спеку, Handover; `--json` — те же поля структурно.
- `DT_TASK=T034 dt context` в основной копии: резолвит T034 и печатает строку
  «задача T034 живёт в <worktree>».
- Непривязанная сессия (ветка `main`, нет `DT_TASK`/current-task): признак
  непривязанности + список `doing`, exit 0, без предупреждений.
- `dt context --hook` всегда exit 0; при сломанном store — пустой вывод, exit 0;
  `additionalContext` ≤ 2000 символов.
- Расхождение BACKLOG печатается только при наличии управляемого блока и
  ненулевой дельте; иначе строки нет.
- После `dt context` в привязанной сессии `by-worktree/<slug>/context.line`
  содержит `T<NNN> [status] title`.
- 4 гейта зелёные; coverage ≥ 80% на новом коде.

## 5. Key Entities

- **resolved task id** — результат порядка §309; `None` = непривязанная.
- **SessionContext** — собранная модель вывода: задача (или `None`), блокеры,
  расхождение BACKLOG (`added/removed` + флаг «блок есть»), расхождение
  каталога (путь worktree задачи vs cwd), список `doing` для непривязанной.
- **context.line** — строка statusline `T<NNN> [status] title`
  (`context_line`, T039), пишется под slug cwd.
- **hook payload** — `{hookSpecificOutput:{hookEventName:"SessionStart",
  additionalContext}}`; бюджет 2000 симв.
- **основная рабочая копия** — корень главного worktree (`main_worktree`,
  новый публичный хелпер в `paths.py`); её BACKLOG.md — эталон для расхождения.

## 6. Assumptions & Constraints

- `git` в PATH; вне git — ветки/worktree нет, резолв падает на `current-task`
  (по slug cwd) или непривязанность; store резолвится через `DT_HOME`/`paths`.
- Разрешение по ветке берёт **префикс** `T<NNN>` из `T<NNN>-slug` — соглашение
  об именовании (T039).
- Основная копия для BACKLOG-расхождения берётся из git-common-dir (T033):
  одинакова из любого worktree; сравнение всегда с ней, не с текущим.
- Бюджет хука 2000 симв. при документированном лимите 10 000 — выжимка, полный
  контекст остаётся в записи задачи и спеке (§354).
- Запись `context.line` идемпотентна и дешёва; не мешает параллельным сессиям
  (файл на slug worktree, §110).

## 7. Out of Scope

- **SessionStart-хук в `.claude/settings.json` и реестр `sessions/<id>.json`**
  — T052 (T051 даёт лишь `--hook` вывод).
- **Statusline-скрипт**, читающий `context.line`, — T054.
- **Детект устаревания Handover** (сравнение с последним коммитом ветки,
  PreCompact-хук) — T055.
- **`dt run` и отказ из чужого каталога** — T056 (T051 даёт лишь строку-детект
  расхождения каталога, не enforcement).
- Запись `current-task` (привязка worktree) — это `dt task start` (T039);
  `dt context` только читает её и обновляет `context.line`.

## Clarify (2 развилки согласованы опросником 2026-08-01)

### Resolved

- **A. Расхождение BACKLOG без управляемого блока** → «Пропускать». Нет
  маркеров `dt backlog sync` в основном BACKLOG.md → строку не печатаем вовсе
  (`has_managed_block` = false). Проект не принял механизм — нечего сравнивать;
  иначе на неадаптированном проекте (в т.ч. сам dreamteam до T042) было бы
  ложное «+все задачи». В `--json` при отсутствии блока `backlog_divergence`
  = `null`.
- **B. Блокеры** → «`deps` со статусом ≠ `done`». Показываем незакрытые
  зависимости — то, что мешает вести задачу сейчас. Согласуется с `dt task
  ready` (задача ready, когда все deps в `done`). `blocks`/обратные зависимости
  не показываем — другое направление, шум.

## Analyze (Claude)

- 🟢 **A1. Расслоение.** Чистое ядро `dt/context.py` (typer-free И git-free):
  `resolve_task_id` (порядок §309), `build_context` (сборка `ContextModel` над
  переданными git-фактами), `render_human`/`context_json`/
  `render_hook_context`. Обёртка `context_cli.py` добывает git-факты
  (`git_context`, `list_worktrees`, `main_worktree`, текст BACKLOG, значение
  `current-task`) и подаёт в ядро. Повторяет T035/T037/T040.
- 🟢 **A2. Резолв — чистая функция над фактами.** `resolve_task_id(dt_task,
  branch, bound)` перебирает источники, принимает только `^T[0-9]{3,}$`; из
  ветки берёт префикс `T<NNN>` (`re.match(r'(T[0-9]{3,})(?:-|$)')`). Разрешённый,
  но отсутствующий в store ID → непривязанность + пометка «висячий» (не падаем).
- 🟢 **A3. worktree задачи — данные, не git-вызов.** `build_context` получает
  `list[WorktreeInfo]` (уже распаршенные факты T036) и матчит `w.branch ==
  task.branch` → путь worktree задачи; `cwd_mismatch` = привязана И
  `task_worktree.resolve() != cwd.resolve()`. Ядро остаётся git-free (тип
  `WorktreeInfo` только под `TYPE_CHECKING`).
- 🟢 **A4. Расхождение BACKLOG.** `main_worktree()` (новый публичный хелпер в
  `paths.py` над приватным `_main_worktree`) даёт корень основной копии; её
  BACKLOG.md читается обёрткой. Ядро зовёт `backlog_divergence` (T040) **только
  если** `has_managed_block` (развилка A) и дельта ненулевая. Основная копия —
  из git-common-dir → одинакова из любого worktree (§217/§880).
- 🟢 **A5. `--hook` никогда не блокирует (§356).** Весь сбор в `try/except
  Exception` → любая ошибка = exit 0 и **пустой** вывод. Успех → печать
  `{hookSpecificOutput:{hookEventName:"SessionStart",additionalContext}}`;
  `additionalContext` = человекочитаемый рендер, обрезанный до 2000 симв.
  (`BLE001` в ignore — широкий except здесь дизайн-обязателен).
- 🟢 **A6. Запись `context.line`.** При привязанной сессии обёртка пишет
  `by-worktree/<slug>/context.line` = `context_line(task)` под slug **cwd**
  (§1068) — идемпотентно, дёшево, файл на slug (не гонки, §110). `current-task`
  **не** трогаем (это `dt task start`). В непривязанной — не пишем.
- 🟢 **A7. Транскрипты не читаем (§358).** Резолв только по `DT_TASK`/ветке/
  `current-task`; никакого доступа к `~/.claude/projects/**/*.jsonl`.
- 🟢 **A8. Вне git.** `git_context` → `(None, None)`; `main_worktree`/
  `list_worktrees` бросают `DtHomeError` → обёртка деградирует (пустой BACKLOG,
  пустой список worktree), резолв падает на `current-task` (по slug cwd, если
  есть) или непривязанность. Хук при этом всё равно exit 0.
- 🟢 **A9. Граница с T052/T054/T055.** T051 — только команда и `--hook` вывод;
  сам хук в `settings.json` и `sessions/<id>.json` — T052; statusline-скрипт —
  T054; детект устаревания Handover — T055 (см. Out of Scope).
