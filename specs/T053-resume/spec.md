## 1. Overview

Двадцать первая по дизайну (карточка T021), репозиторный T053, эпик E9
(`deps: T052, T036`), замыкающий шаг критического пути
(T033 → T034 → T051 → T052 → **T053**). T052 научил SessionStart-хук
**самостоятельно** вести реестр `$DT_STORE/sessions/<TASK_ID>.json`
(`session_id`, `cwd`, `last_seen`). T053 добавляет **потребителя** этого
реестра — команду `dt resume`, которая после перезагрузки машины читает
реестр и выдаёт человеку точные команды восстановления раскладки: по одному
окну на активную задачу, `cd` в её worktree и команда `claude`, поднимающая
ту же сессию.

Единственное физическое действие человека при восстановлении после reboot
(§78): один вызов `dt resume --tmux`.

Три формы вывода (§372–377):

```
dt resume            # таблица: задача, статус, ветка, worktree, команда восстановления
dt resume --tmux     # одноразовый shell-скрипт раскладки (человек читает и запускает)
dt resume T034       # одна команда восстановления для конкретной задачи
```

## 2. Сценарии использования

- **Восстановление раскладки после reboot.** Живых процессов нет, но
  `sessions/*.json` пережили перезагрузку. `dt resume --tmux` печатает
  скрипт: на каждую **активную** задачу — `tmux new-window -n T034 -c <worktree>`
  и `send-keys` команды восстановления. Человек читает скрипт, запускает,
  получает свои окна обратно.
- **Быстрый обзор.** `dt resume` без флагов — таблица активных задач с
  готовой строкой `cd <worktree> && claude --resume <session_id>` в каждой
  строке (можно скопировать одну).
- **Одна задача.** `dt resume T034` — одна строка команды для конкретной
  задачи (в т.ч. для `eval "$(dt resume T034)"` или ручного copy-paste).
- **Транскрипт вычищен (ретенция).** `last_seen` записи старше окна
  ретенции (30 дней по умолчанию, §388): вместо `--resume <id>` (который
  упал бы — транскрипта уже нет) выдаём `cd <worktree> && claude` с
  комментарием-подсказкой прочитать Handover.
- **Сессия не записана в реестр.** `dt resume T034`, когда задача заведена и
  worktree существует, но `sessions/T034.json` нет (хук ни разу не отработал):
  деградация до `cd <worktree> && claude --continue` (§384 — берёт последнюю
  сессию каталога; при правиле «один worktree — одна задача» результат тот же).
- **Пустой реестр.** `dt resume` без единой записи → внятное «нет сессий для
  восстановления», код 0.

## 3. Functional Requirements

### Источник данных и множество задач

- ДОЛЖНА: строить вывод из **реестра** `$DT_STORE/sessions/*.json` (файлы,
  заведённые хуком T052), соединяя каждую запись с записью задачи из store
  по `<TASK_ID>` (имя файла) — для статуса, ветки, заголовка.
- ДОЛЖНА: **таблица** (`dt resume`) и **`--tmux`** показывают только
  **активные** задачи — статус не `done` и не `dropped` (решение Clarify Q2;
  §428 «по всем активным задачам»). Записи реестра завершённых задач молча
  отсеиваются (их транскрипты обычно уже не нужны).
- ДОЛЖНА: запись реестра, чей `<TASK_ID>` **отсутствует** в store (dangling —
  задача удалена), молча пропускается в таблице/`--tmux` (статус неизвестен,
  считать активной нельзя).
- ДОЛЖНА: адресный `dt resume T034` работает и **без** записи реестра (см.
  деградацию), пока задача существует в store; статус задачи на адресную
  форму **не** влияет (можно резюмировать и review-задачу по явному запросу).

### Команда восстановления (одна на задачу)

- ДОЛЖНА: при наличии записи и **свежем** `last_seen` — команда
  `cd <q(worktree)> && claude --resume <session_id>`, где `worktree` берётся
  из `cwd` записи (это каталог, где жила сессия), `<session_id>` — из записи.
- ДОЛЖНА: при **устаревшей** записи (`last_seen` старше окна ретенции, §388) —
  `cd <q(worktree)> && claude` плюс inline-комментарий-подсказка
  `# транскрипт старше N дней — восстанови картину по Handover`.
- ДОЛЖНА: при **отсутствии** записи (только адресная форма) — если worktree
  задачи существует: `cd <q(worktree)> && claude --continue`; worktree берётся
  из `list_worktrees()` по `task.branch`, либо вычисляется `resolve_path`.
- ДОЛЖНА: любой путь в команде **shell-квотиться** (`shlex.quote`) — путь
  worktree может содержать пробелы/спецсимволы; команда предназначена для
  копирования в шелл.
- НЕ ДОЛЖНА: вычислять или обращаться к пути транскрипта
  (`~/.claude/projects/<munged-cwd>/<id>.jsonl`) — раскладка недокументирована;
  «жив ли транскрипт» определяется **по возрасту записи** `last_seen`, а не
  `stat` файла (решение Clarify Q1, ADR; согласовано с acceptance §434/#8
  «ни один компонент не читает внутренние файлы транскриптов»).

### Возраст записи (детект ретенции)

- ДОЛЖНА: `last_seen` парсится как ISO-8601 (tz-aware, offset пишет T052);
  «устарела», если `now - last_seen > RETENTION_DAYS` (константа = 30, дефолт
  `cleanupPeriodDays` Claude Code).
- ДОЛЖНА: **непарсящийся** `last_seen` трактуется как свежий (выдаём
  `--resume`) — best-effort; лучше предложить резюм, чем спрятать сессию.
- ДОЛЖНА: `now` пробрасывается в чистое ядро параметром (тестируемость);
  ядро само `datetime.now()` не зовёт.

### Формы вывода

- ДОЛЖНА: **таблица** — по строке на задачу: `T034  [doing]  <branch>
  <worktree>  <команда>`; выравнивание читаемое, но без внешних зависимостей.
- ДОЛЖНА: **`--tmux`** — shell-скрипт на stdout: шапка-комментарий (что это и
  что скрипт делает), затем на каждую задачу `tmux new-window -n <TASK_ID>
  -c <q(worktree)>` и `tmux send-keys -t <TASK_ID> <q(recovery)> Enter`. Имя
  окна = `<TASK_ID>` (§386/§414). Скрипт человек **читает и запускает сам** —
  dreamteam его не исполняет (граница «не диспетчер процессов», §52/§619).
- ДОЛЖНА: **адресная** форма (`dt resume T034`) — одна строка команды на
  stdout (без таблицы), пригодная для `eval`.
- ДОЛЖНА: **`--json`** — машиночитаемый список записей (консистентно с
  остальными `dt`-командами): `task_id`, `status`, `branch`, `worktree`,
  `session_id` (или null), `mode` (`resume`/`continue`/`stale`), `command`.
- НЕ ДОЛЖНА: совмещать `--tmux` и `--json` — взаимоисключающие; при обоих —
  ошибка (код 1) с внятным сообщением.

### Разделение слоёв (конвенция репо)

- ДОЛЖНА: чистое ядро — новый модуль `dt/resume.py`, **typer-free И git-free**
  (как `context.py`/`worktrees.py`): вычисление устаревания, сборка
  `ResumeEntry`, рендер таблицы/tmux/json. Чистые функции над предсобранными
  фактами (записи реестра + карта задач + `now` + факты worktree).
- ДОЛЖНА: перечисление записей реестра — helper в `dt/sessions.py`
  (`read_all_session_records`, FS-доступ ядру разрешён, как в T052).
- ДОЛЖНА: обёртка `resume_cli.py` добывает git-факты (`list_worktrees`) и
  время (`current_timestamp`/`datetime.now`), зовёт ядро; монтируется
  top-level командой `resume` в `cli.py` (как `context`/`board`).

## 4. Success Criteria

- Реестр с `sessions/T034.json` (`session_id=S`, свежий `last_seen`), задача
  `T034` в статусе `doing`, worktree на месте: `dt resume` печатает строку
  `T034  [doing]  T034-slug  <wt>  cd <wt> && claude --resume S`; код 0.
- Та же ситуация, `last_seen` 40 дней назад: команда — `cd <wt> && claude`
  с комментарием про Handover (не `--resume`).
- `sessions/T041.json` есть, но задача `T041` в `done`: в `dt resume` и
  `--tmux` строки **нет**; `dt resume T041` (адресно) команду всё же даёт.
- `dt resume T034` без `sessions/T034.json`, worktree существует:
  `cd <wt> && claude --continue`.
- `dt resume T999` (нет в store): ошибка код 1, внятное сообщение.
- `dt resume --tmux`: валидный shell-скрипт, пути shell-квотированы, имя окна
  = `T034`; парсинг глазами показывает по окну на активную задачу.
- `dt resume --json`: список объектов с полями выше; `--tmux --json` вместе →
  ошибка код 1.
- Пустой реестр: `dt resume` → «нет сессий», код 0.
- Все 4 pre-push проверки зелёные; coverage `src/` ≥ 80% (новые
  `dt/resume.py` и helper покрыты).

## 5. Key Entities

- **`ResumeEntry`** (NamedTuple ядра) — одна восстанавливаемая задача:
  `task_id`, `status`, `branch`, `worktree` (str), `session_id` (str|None),
  `mode` (`resume`/`stale`/`continue`), `command` (готовая строка `cd … &&
  claude …`).
- **Запись реестра** (`sessions/<TASK_ID>.json`, из T052) — вход: `session_id`,
  `cwd` (= worktree сессии), `last_seen` (tz-aware ISO-8601).
- **`RETENTION_DAYS`** — окно ретенции транскриптов (30, дефолт CC
  `cleanupPeriodDays`); порог устаревания записи.

## 6. Assumptions & Constraints

- `dt` есть в PATH; отсутствие `dt`/tmux не ломает проект (§435) — но `dt
  resume` сам по себе бесполезен без `dt`, это ожидаемо.
- Реестр — **удобство**, не источник истины (§437–439): транскрипты чистятся
  через 30 дней, поэтому актуальный Handover (T055) остаётся обязательным, а
  `dt resume` честно деградирует, а не выдаёт падающую команду.
- `--tmux`-скрипт исполняется человеком **внутри** уже запущенного tmux
  (создаёт окна в текущем сервере); dreamteam скрипт не запускает и tmux-сервер
  не поднимает (граница «не диспетчер», §619). Отсутствие tmux при запуске
  скрипта — забота человека, не `dt resume` (он лишь печатает текст).
- `cd`-цель — `cwd` из записи реестра (буквально каталог, где жила сессия);
  для формы без записи — путь worktree из `list_worktrees()`/`resolve_path`.
- Только `tmux rename-window`/`new-window`/`send-keys` в скрипте — но их
  **исполняет человек**, не агент; единственная агентская tmux-операция
  (rename-window) уже сделана в T039 (§419), здесь агент tmux не зовёт.

## 7. Out of Scope

- **Запись реестра / SessionStart-хук** — T052 (готово); T053 только читает.
- **Statusline** (`context.line`, shell-скрипт < 50 мс) — T054.
- **Handover как живая секция, PreCompact-хук, детект устаревания Handover** —
  T055. `dt resume` лишь *ссылается* на Handover в подсказке для устаревшей
  записи, но не читает и не проверяет его свежесть.
- **Секция методики `sessions`** (правила поведения агента вокруг resume) —
  T047.
- **Догфудинг `dt resume` в самом репозитории dreamteam** — store пуст до
  `dt migrate tasks` (T042).
- **Автозапуск раскладки** (dreamteam исполняет tmux вместо печати скрипта) —
  сознательно отвергнуто (§52/§619 «не диспетчер процессов»).
- **Чтение `cleanupPeriodDays` из настроек Claude Code** для точного окна
  ретенции — MVP берёт дефолт 30; при потребности — отдельная задача.
- **Стат/чтение файлов транскриптов** — отвергнуто (ADR; §434/#8).

## Clarify (заполняется Claude)

Слепые зоны разрешены против дизайн-документа E9. Две развилки, реально
принадлежащие Разработчику, вынесены опросником — ответы ниже.

### Resolved (с ответами)

- **Q1 (§388 — как проверять «жив ли транскрипт»?)** → **По возрасту записи.**
  Транскрипты не трогаем вовсе (принцип T052: опираемся только на
  документированные поля хука, §358). `last_seen` старше 30 дней ⇒ выдаём
  `claude` + подсказку про Handover; иначе `claude --resume <id>`. Отвергнуты:
  *стат транскрипта* (жёсткая привязка к недокументированной раскладке
  `~/.claude/projects/<munged-cwd>/`, ломкость при смене версии CC, конфликт с
  acceptance #8) и *всегда `--resume`* (нарушает §388 — команда упадёт). ADR.
- **Q2 (из какого множества строить таблицу?)** → **Только активные.** Записи
  реестра, чья задача не `done`/`dropped`. Соответствует §428 «по всем
  активным задачам»; завершённые задачи не засоряют раскладку. Адресная форма
  (`dt resume T034`) статусом не ограничена.
- **Q (edge): dangling-запись (задача удалена из store)?** → В таблице/`--tmux`
  пропускается (статус неизвестен ⇒ активной считать нельзя). Адресный вызов
  на несуществующую задачу — ошибка код 1.
- **Q (edge): непарсящийся `last_seen`?** → Трактуем как свежий (best-effort
  `--resume`): лучше предложить резюм, чем молча спрятать сессию.
- **Q (safety): пробелы/спецсимволы в пути worktree?** → `shlex.quote` на всех
  путях в командах и tmux-скрипте.
- **Q (scope): `--tmux` запускает tmux или печатает скрипт?** → Печатает
  скрипт; человек читает и запускает (§386, граница «не диспетчер», §619).
- **Q (integrations): `--tmux` + `--json`?** → Взаимоисключающие; оба вместе —
  ошибка код 1.

## Analyze (заполняется Claude)

Чистый проход. Issues:

- 🟢 **Note.** `dt/resume.py` git-free и typer-free: git-факты
  (`list_worktrees`) и время добывает обёртка `resume_cli.py`, ядро — чистые
  функции над предсобранными данными (образец — `context.py`/`worktrees.py`).
  FS-перечисление реестра — в `sessions.py` (`read_all_session_records`),
  где FS уже разрешён (T052).
- 🟢 **Note.** Возраст: ядро принимает `now` параметром, `is_stale(last_seen,
  now, retention_days)` парсит tz-aware ISO (offset пишет `current_timestamp`
  T052). Непарсящийся `last_seen` → `False` (свежий). `now` — tz-aware из
  обёртки; сравнение aware-aware корректно (DTZ соблюдён).
- 🟢 **Note.** shell-инъекция: worktree-путь из записи реестра/`cwd` не
  валидируется git'ом, поэтому все пути в `cd`/`-c`/`send-keys` проходят через
  `shlex.quote`. `session_id` — из реестра; в команду он идёт как аргумент
  `--resume`, но для консистентности тоже квотируется.
- 🟢 **Note.** Адресная форма без записи: worktree резолвится
  `resolve_path(worktrees_dir(), task.branch, list_worktrees())`; если задача
  без ветки (не стартовала) и worktree нет — ошибка «нечего восстанавливать,
  сначала `dt task start`».
- 🟢 **Note.** `--tmux`+`--json` проверяется в обёртке до сбора данных;
  ранний выход код 1. Согласуется с паттерном валидации в `cli.py apply`
  (`on_conflict` check).
- 🟢 **Note.** Coverage: ядро (`is_stale` границы, три `mode`, рендеры
  таблица/tmux/json, квотирование пути с пробелом) — юнит-тестами; путь CLI
  (пустой реестр, dangling, адресная форма, `--tmux --json` конфликт) —
  CLI-тестами с предсозданным store (см. память о смешивании stderr в
  CliRunner — store предсоздаём в фикстуре).
- 🟢 **Note.** Порядок строк таблицы/`--tmux` детерминирован — сортировка по
  числовой части `<TASK_ID>` (как `context._id_num`), иначе `glob` даёт
  случайный порядок ФС.
