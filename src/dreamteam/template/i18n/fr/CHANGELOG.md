# Changelog

Historique des changements notables. Format — un
[Keep a Changelog](https://keepachangelog.com/) simplifié.

Les entrées sont regroupées par versions ou par dates de release.
Pour les projets sans versioning formel, utiliser la date comme
titre est acceptable.

Catégories :
- **Added** — nouvelle fonctionnalité.
- **Changed** — changements dans une fonctionnalité existante.
- **Fixed** — corrections de bugs.
- **Removed** — fonctionnalité supprimée.
- **Deprecated** — marqué pour suppression, mais fonctionne encore.
- **Security** — changements importants pour la sécurité.

Si un changement est lié à une tâche de `BOARD.md` / `BACKLOG.md`,
l'entrée **doit** contenir le T-ID entre parenthèses, par exemple :
`Added: Aperçu des posts dans Telegram (T<NNN>).` Cela préserve
l'unicité des T-IDs entre releases — `CHANGELOG.md` est l'unique
stockage persistant des numéros des tâches terminées (voir la règle
de numérotation dans `README.md`).
