# Changelog

显著变更的历史。格式 —— 简化版
[Keep a Changelog](https://keepachangelog.com/)。

条目按版本或 release 日期分组。对于没有正式版本管理的项目，使用
日期作为标题也是可以的。

类别：
- **Added** —— 新功能。
- **Changed** —— 对现有功能的变更。
- **Fixed** —— bug 修复。
- **Removed** —— 删除的功能。
- **Deprecated** —— 标记为待删除，但仍工作。
- **Security** —— 与安全相关的重要变更。

如果某项变更与 `BOARD.md` / `BACKLOG.md` 中的任务相关，条目
**必须**在括号中包含 T-ID，例如：`Added: Telegram 中的 post
预览 (T<NNN>).` 这保证 T-ID 在 release 之间的唯一性 ——
`CHANGELOG.md` 是已完成任务编号的唯一持久化存储（见 `README.md`
中的编号规则）。
