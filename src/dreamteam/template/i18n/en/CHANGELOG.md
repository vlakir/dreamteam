# Changelog

History of notable changes. Format — a simplified
[Keep a Changelog](https://keepachangelog.com/).

Entries are grouped by versions or release dates. For projects
without formal versioning, using the date as the header is
acceptable.

Categories:
- **Added** — new functionality.
- **Changed** — changes to existing functionality.
- **Fixed** — bug fixes.
- **Removed** — removed functionality.
- **Deprecated** — flagged for removal but still working.
- **Security** — security-relevant changes.

If a change is tied to a task from `BOARD.md` / `BACKLOG.md`, the
entry **must** contain the T-ID in parentheses, for example:
`Added: Post preview in Telegram (T<NNN>).` This preserves T-ID
uniqueness across releases — `CHANGELOG.md` is the only persistent
store of completed task numbers (see the numbering rule in
`README.md`).
